Mobile install options: what we know so far

  • Already cross-platform: our Godot/GDScript project can target macOS, Android, and iOS. Godot export documentation.
  • Reuse the game: gameplay, levels, artwork, and most code should carry over; a language rewrite is not required to investigate mobile versions.
  • Mobile work: add touch controls, adapt layouts and safe areas, and test controller input, performance, audio, and app suspension on real devices.
  • Separate packages: produce an Android APK and an iOS development build with the necessary platform tools and signing. Neither mobile version has been validated yet.
  • Kotlin comparison: Kotlin Multiplatform and Compose can share code and UI across these platforms; our current recommendation is to keep Godot for this action game. No migration is planned. Kotlin Multiplatform FAQ.

Android: investigate a signed APK installed directly on a test device, using developer deployment or the device’s permitted local-install flow. Confirm the actual OS, device and regional requirements when testing. Godot provides an Android export path requiring Java and Android SDK setup. Godot Android export guide.

iOS: the initial equivalent is a development build installed from Xcode on the Mac. Godot exports an Xcode project; public App Store publication is not required for this test. Godot iOS export guide.

A free Apple Account can use an Xcode Personal Team for personal-device testing, with limitations including seven-day provisioning profiles that require rebuilding/reinstalling after expiry. Evaluate paid-program development, ad hoc distribution or TestFlight only if we need broader testing. Apple account and testing limits.

Research gate: verify these paths with our installed Godot/Xcode versions and actual devices. A successful export alone does not prove that touch controls, performance, or signing are practical.
